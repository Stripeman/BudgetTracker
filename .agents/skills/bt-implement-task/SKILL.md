description: Implement an authorized BudgetTracker requirement or accepted finding with focused validation and maintained project state.
---

Read governance, the full brief/register, project state and `.codex/agents/README.md`. Operate as the primary implementation owner or hand off to primary-implementation-agent; never have two simultaneous writers. Preserve Git baseline and local work.

Define the BT requirement, observable acceptance, dependencies, non-goals and adjacent behavior before editing. Use archaeology for potential reuse. Security, permissions, encrypted backups and tested isolated restores precede financial features. Trace the canonical path and implement meaningful positive/negative tests for risky behavior; avoid tests that merely repeat implementation. Run focused checks and required repository gates. Use the selective review matrix, apply accepted findings and record retests.

For runtime checks, follow verified BudgetTracker local-start instructions only when they exist; never use TaskTracker ports, forged roles or storage by assumption. Report unavailable runtime honestly. Maintain .gitignore, README, state and requirement evidence. Scan secrets and inspect staged paths/content before commits. No main/master pushes, merges, Production deployments or private data commits.
